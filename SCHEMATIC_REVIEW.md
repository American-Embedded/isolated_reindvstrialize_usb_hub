**Implementation update:** The findings below describe the original revision. Schematic fixes are now implemented; software I²C is intentional and retained. See [SCHEMATIC_CHANGES.md](SCHEMATIC_CHANGES.md) for the current circuit, validation, and remaining PCB/firmware work.

Review of the saved schematic at commit `f49a33c`, 2026-09-05. **Do not release this revision for fabrication yet.** Several electrical issues need correction. This is a review; no schematic, PCB, or component selection was changed.

Inspected the five rendered sheets, enlarged the isolator/hub/MCU circuits, traced the exported XML netlist (130 components, 137 nets), ran KiCad 10.0.6 ERC including exclusions, and compared critical circuits and pinouts with manufacturer documentation. Generated evidence is in [build/schematic-review](build/schematic-review/), including [schematic PDF](build/schematic-review/schematic.pdf), [ERC JSON](build/schematic-review/erc.json), and [netlist](build/schematic-review/netlist.xml). Build artifacts are ignored by Git.

The architecture is J1 → ISOUSB211 U16 → CH338F U7 → four gated USB ports; U4 is attached to hub port 5 and controls their enables/fault monitoring. J2 supplies the downstream domain. GND and GND2 are separate in the schematic. The downstream ports share GND2 and are not isolated from each other. Data passes transparently through enabled ports; the schematic contains no USB protocol inspection stage.

**Confirmed issues, in priority order**

1. **High — J2 cannot reliably start from a USB-C supply: missing Rd resistors.** J2.A5 connects only to U4.28 and U6's first protection channel; J2.B5 connects only to U4.1 and U6's second channel. Neither CC net has a 5.1kR pulldown. U4 itself depends on J2 power. Add independent CC1/CC2 pulldowns to GND2 to establish the sink termination before firmware runs. WCH's evaluation schematic uses external 5.1k resistors. Test cold startup with a C-to-C cable in both orientations, including an unprogrammed MCU. [WCH evaluation schematic](https://github.com/openwch/ch32x035/blob/main/EVT/PUB/CH32X035SCH.pdf)

2. **High — U16's internal 3.3 V regulators are paralleled with U3/U5.** U16.1/.28 receive their respective 5 V rails, while .2/.27 are tied to the external AP2112 outputs. This is not a documented supply configuration. Either leave each V3P3V pin as a locally bypassed internal-regulator output, or join that side's VBUS and V3P3V pins to external 3.3 V. Preserve a valid VCC supply. Do not simply short existing 5 V and 3.3 V nets. [TI ISOUSB211, pin descriptions and §7.3.1](https://www.ti.com/lit/ds/symlink/isousb211.pdf)

3. **High — U16's 1.8 V decoupling is incomplete.** Only C3=1uF serves pins 4/11 and C24=1uF serves pins 18/25. TI specifies local 2uF, 100nF and 10nF networks at the four 1.8 V pin locations. Provide the specified networks, effective capacitance under bias, and short local returns. This is a substantial departure with high-speed reliability implications, not proof of an observed failure. [TI ISOUSB211, §8.3 and Figure 8-9](https://www.ti.com/lit/ds/symlink/isousb211.pdf)

4. **High — output USB-C ports lack attachment detection.** At J5/J7/J9/J11, CC1 and CC2 only have 56kR pullups to unswitched VBUS_ISO. There is no path to a CC detector or MCU input. Consequently firmware cannot distinguish an unattached port from a valid sink before enabling VBUS, or detect CC detach to remove it. The pullup values are appropriate for default-current advertisement from 5 V, but do not implement a Type-C source state machine. Add CC detection tied into the existing power-control decision and verify detach/discharge timing. A USB connection event on D+/D− cannot replace pre-power CC detection. [USB-IF Type-C functional tests, source state-machine tests](https://www.usb.org/sites/default/files/USB%20Type%20C%20Functional%20Test%20Specification%202021%2005%2020.pdf)

5. **Medium — the debug RESET connection does not reset this MCU package.** J3.3 goes to U4.4/PC3. WCH restricts PC3's external-reset function to QSOP28 and TSSOP20; this device is CH32X035G8U6 in QFN28. Document the actual recovery procedure and remove or relabel the misleading reset connection. The DIO/DCK connections themselves match pins 25/24. An ARM-style connector does not establish ARM debug-protocol compatibility. [WCH CH32X035 datasheet, pin-function table notes](https://xpulabs.github.io/files/datasheet/CH32X035DS0_EN.PDF)

6. **Medium — SCL/SDA require software I²C.** U4.PB10/.21 and PB11/.22 are wired to U7.SMBCLK/.18 and SMBDAT/.17. These MCU pins do not provide the hardware I²C functions listed in its pin table. Software open-drain I²C/SMBus is possible; using the hardware peripheral requires a pin reassignment with USB/debug conflicts checked. Record the intended implementation so firmware does not assume these labels imply peripheral routing. [WCH CH32X035 pin table](https://xpulabs.github.io/files/datasheet/CH32X035DS0_EN.PDF)

7. **Medium — the electronic current limit is approximately 1.18 A per port.** R5–R8=51kR and CH217A's relation `Iset = 60000 / Rset` give 1.176 A nominal. F3–F6 are labeled 500mA, but a resettable fuse is not an instantaneous 500 mA limiter. Decide the intended limit and coordinate switch tolerance, fuse trip behavior, cable losses and total input budget. Four nominal switch thresholds sum to about 4.7 A before internal consumption; F2's 3A marking does not resolve simultaneous fault loading. [WCH CH217 v1.3, §5.4](https://atta.szlcsc.com/upload/public/pdf/source/20260518/11202443994CC8E8AD111F5D5C5E697B.pdf)

8. **Medium — CH217 input bypassing is missing locally.** C30/C31, C32/C35, C36/C38 and C39/C41 are all on VOUT. VIN has only shared C6+C21=5.7uF shown elsewhere. WCH recommends at least 10uF at VIN. Resolve input transient support and placement while checking J2 inrush; indiscriminately adding four large capacitors directly across J2 is not a complete solution. [WCH CH217 v1.3, pin descriptions](https://atta.szlcsc.com/upload/public/pdf/source/20260518/11202443994CC8E8AD111F5D5C5E697B.pdf)

**Design decisions and validation still needed**

| Item | Evidence and action |
| --- | --- |
| Hub PD-disable strap | R17=56kR pulls U7.21 down. This pin has an internal pullup and samples PD enable during reset; WCH's ordinary-hub reference uses 10kR. Verify the worst-case low level or follow that reference value. This is an unresolved strap-margin concern, not a measured boot failure. [WCH CH338 v1.2](https://atta.szlcsc.com/upload/public/pdf/source/20250604/33B7EB63DA58DDDA601A5A5911A2B220.pdf) |
| Host power/fault semantics | U7.21/PWREN only reaches R17; U7.22/OVCUR is NC. Port enables and fault outputs terminate at U4. The MCU must implement the intended host-visible behavior; the CH338F supports ganged hardware control. Confirm hub descriptors and fault reporting. [WCH CH338](https://doc.inmys.ru/hash/2a285fb2d39d956a1096be8a85274412/CH338F.pdf) |
| Input current and voltage policy | Four 500 mA loads already require 2 A plus electronics. A USB-C supply may advertise less. U4 must respect J2's available current and keep this directly connected rail at 5 V. Negotiating 9/12/20 V would overvoltage downstream circuitry. No conversion stage is present. |
| Power dissipation | U5 feeds U4, U7, switches, LEDs and U16.VCC2. Compute worst-case current and `(VIN−3.3 V) × I` after correcting U16; check actual SOT-23 copper area and temperature. A 600 mA regulator rating alone does not establish thermal margin. [AP2112](https://www.diodes.com/part/view/AP2112?BackID=9304) |
| Output transient behavior | Each port has 57uF nominal before its fuse and bead, with no separate capacitor at connector VBUS. Measure connector droop and recovery under plug-in/load steps; account for capacitor bias loss and all series impedances. |
| Unspecified beads | FB1–FB4 have only a generic value. Their DC drop and transient behavior cannot be assessed. Prefer a direct low-impedance connection unless an identified noise problem justifies a bead. Keeping one requires impedance at actual bias, DCR, resonance/damping and load-step evidence. |
| Crystal qualification | Y2 lacks an exact part. Its 25 MHz crystal, 30pF XO capacitor and 4.7MR XI pulldown topology matches WCH's reference; the asymmetric network is not inherently an error. Verify the selected crystal's load, ESR and drive level. [WCH Figure 8-4](https://atta.szlcsc.com/upload/public/pdf/source/20250604/33B7EB63DA58DDDA601A5A5911A2B220.pdf) |
| Equalization options | JP1–JP4 are DNP, omitted from the BOM, and have no footprint. U16's EQ pins therefore float. Floating is legal, but adjustment is unavailable as drawn; document this choice or provide real strap footprints. [TI ISOUSB211, §7.3.9](https://www.ti.com/lit/ds/symlink/isousb211.pdf) |
| Isolation boundary | No schematic connection bridges GND/GND2. Actual isolation depends on PCB clearance, mounting hardware, enclosure and the external supply. Powering J2 from another port on the same host can externally join the grounds. No voltage rating is established by this review. |
| Part ratings | Most capacitors/fuses/crystal/beads have no exact MPN or electrical ratings. Confirm capacitor dielectric/voltage/bias performance, fuse hold/trip/DCR behavior and connector ratings before ordering. |

**Checks that passed at schematic level**

- D+/D− polarity is consistent through J1, U16, U7, each TS3USB221E, and all output connectors. The duplicate USB-C data contacts join the correct nets. The four hierarchical sheets keep their local data, CC and VBUS-output nets separate.
- Port mapping is: port 1→J5/U8/U20; port 2→J9/U11/U22; port 3→J11/U12/U23; port 4→J7/U9/U21. The sheet names are ordered differently, but the enable/fault pairs follow the right connector.
- U20–U23 have S grounded, selecting D1 when OE is low. Their shared active-low control with the CH217A is logically consistent; 51kR pullups establish disabled state once 3.3 V is present. Test ramp/brownout behavior separately. [TI TS3USB221E truth table](https://www.ti.com/lit/ds/symlink/ts3usb221e.pdf)
- R18=9.1kR selects the hub's SMBus mode. USB port 5 reaches U4's USB pins, while unused ports 6/7 are NC. Configure unused ports and the internal device's removable status deliberately. [WCH CH338 configuration tables](https://atta.szlcsc.com/upload/public/pdf/source/20250604/33B7EB63DA58DDDA601A5A5911A2B220.pdf)
- USBLC6-2SC6 pin pairs 1/6 and 3/4, ground pin 2 and VBUS pin 5 are connected consistently. Their ESD function does not constitute sustained overvoltage protection. Physical routing and system ESD testing remain necessary. [ST USBLC6-2](https://www.st.com/resource/en/datasheet/usblc6-2.pdf)
- AP2112 VIN/EN/GND/VOUT pin assignments and nominal 1uF local input/output capacitors match the basic application circuit. This does not clear the U16 regulator conflict or thermal checks. [Diodes AP2112](https://www.diodes.com/datasheet/download/AP2112.pdf)

**ERC and drawing quality**

ERC reported 32 entries: 3 active power-not-driven errors, 24 active warnings (21 capacitor library mismatches and 3 unspecified-pin connections), plus 5 excluded error records. The exclusions include stale empty-item records. No active unconnected-pin error was reported. The power errors need source flags after checking the real supplies; they are not by themselves evidence of absent physical power.

ERC coverage is weakened by symbol metadata: U16's supply pins are passive and GND2 pins unspecified; U7.PWREN and HUB_CC_CTL are typed as inputs, SMBCLK as output despite its selected SMBus role, and core supplies are unspecified. Correct electrical types according to actual/multiplexed function. Preserve pin numbers and names. Resolve C_Small library drift separately from electrical changes; do not blindly update custom symbols.

The drawings are readable when enlarged but sparse at full-page scale. The root schematic has substantial unused space and no functional block titles; the output sheets repeat a compact circuit in a mostly empty page. Stacked supply pins obscure local decoupling needs. Global data labels on the USBLC symbols are crowded against pin text, and large DNP crosses distract on test points/jumpers. Fill in title/revision/client fields, add power-domain and active-low control notes, identify software I²C, and improve block grouping. Keep the repeated output hierarchy.

This review does not sign off PCB routing, symbol-to-footprint geometry, USB eye diagrams, EMI, hardware startup, firmware, or insulation performance. The next validation should cover cold C-to-C startup, both connector orientations, every port enable/fault path, input-current limits, load-step/short-circuit recovery, supply temperatures, USB enumeration at all supported speeds, and suspend/resume.
